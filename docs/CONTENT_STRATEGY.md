# 博客内容结构

这份博客建议长期保持 3 个顶层板块：

1. 工程实践
2. 技术思考
3. 生活随记

这套分法的目标不是“把所有东西分得很细”，而是让读者一眼知道这篇文章是：

- 能直接学到做事方法
- 能看到你的判断和思考
- 能认识真实的你

## 为什么这样分

参考当前主流技术博客和工程团队博客，常见做法大致有 3 种：

- 按主题分：例如工程、架构、前端、数据、AI、职业发展
- 按读者意图分：例如教程、观点、更新、案例
- 按内容形态分：例如文章、笔记、链接、周记

对个人博客来说，最稳的做法通常不是把顶层分类开得很多，而是先固定 3 到 5 个“内容车道”，再用 tags 补足细节。

## 顶层分类建议

### 1. 工程实践

这是你的“求职展示面”。

适合放：

- SRE 学习笔记
- 云原生实战
- Kubernetes / Docker / Linux / Terraform / CI/CD
- 故障排查与复盘
- 监控、告警、可观测性
- 项目搭建记录
- 面试题拆解与实验验证

不适合放：

- 纯情绪表达
- 行业吐槽
- 只有观点、没有实践支撑的文章

建议子分类：

- SRE 与可靠性
- 云原生与平台
- 自动化与交付
- 项目与复盘
- 求职与面试

推荐 tags：

- SRE
- Kubernetes
- Linux
- Docker
- Terraform
- Prometheus
- Grafana
- CI/CD
- Incident
- Observability

### 2. 技术思考

这是你的“判断力展示面”。

适合放：

- 对技术行业的理解
- 学习方法与知识管理
- 职业路线思考
- AI 对工程工作的影响
- 工程文化、协作、写作、复盘
- 从一个技术现象出发的深度观点文

不适合放：

- 大量命令行步骤
- 工具安装教程
- 纯生活记录

建议子分类：

- 学习方法
- 职业发展
- 行业观察
- 工程方法论
- 写作与表达

推荐 tags：

- Career
- Learning
- AI
- Writing
- Productivity
- Methodology

### 3. 生活随记

这是你的“人格展示面”。

适合放：

- 日常碎碎念
- 周记 / 月记
- 阅读、观影、旅行
- 作息、训练、状态变化
- 某个阶段的人生感受

不适合放：

- 假装技术化的生活流水账
- 明明是技术观点却塞进生活分类

建议子分类：

- 周记与阶段总结
- 阅读与观影
- 生活片段
- 城市与出行

推荐 tags：

- Weekly Notes
- Reading
- Travel
- Fitness
- Journal

## 最好用的判断规则

发文前只问自己 1 个问题：

- 这篇文章主要是在“教人做事”吗？放到 `工程实践`
- 这篇文章主要是在“表达判断”吗？放到 `技术思考`
- 这篇文章主要是在“记录生活”吗？放到 `生活随记`

如果一篇文章同时沾边两个方向，按“读者最期待得到什么”来选顶层分类，另一个方向交给 tags。

## 你这个博客最适合的写法

建议你把“分类”和“标签”分工明确：

- 分类：只保留 3 个顶层车道，长期稳定
- 标签：具体技术和话题，允许变多

也就是说：

- 不要把 `Kubernetes`、`Linux`、`Prometheus` 这些做成顶层分类
- 它们更适合做 tags
- 顶层分类应该尽量几年后看也不需要大改

## 推荐 front matter 模板

### 工程实践

```yaml
---
title: 我如何搭一个最小可用的 Kubernetes 监控方案

categories:
  - 工程实践
tags:
  - SRE
  - Kubernetes
  - Prometheus
  - Observability
---
```

### 技术思考

```yaml

categories:
  - 技术思考

  - Writing
  - Learning
  - Career

```

```yaml

categories:
  - 生活随记
tags:
  - Weekly Notes
  - Journal
---
```

## 现阶段最推荐的最终方案

你的博客先用这 3 个顶层分类就够了：

- 工程实践
- 技术思考
- 生活随记

如果以后文章数明显变多，再在每个顶层分类下面用 tags 慢慢长出自己的结构。
